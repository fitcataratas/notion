**Novidades da versão 1.4:**

## 4. Colocar no servidor novo (Ubuntu)

> Passo a passo completo para o TI: arquivo **SERVIDOR.md** (e `ferramentas/nginx-gestao.conf`).


1. Instale Docker e Nginx. Copie esta pasta para o servidor (ex.: `/opt/gestao`) e siga o passo 1 com
   `APP_URL=https://gestao.seudominio.com.br` e `APP_ENV=producao` no `.env`.
2. Nginx (arquivo `/etc/nginx/sites-available/gestao`):

```nginx
server {
    listen 80;
    server_name gestao.seudominio.com.br;
    client_max_body_size 20m;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

3. Ative o cadeado (HTTPS): `sudo certbot --nginx -d gestao.seudominio.com.br`.
   Com `https://` no `APP_URL`, o login só funciona por conexão segura.
4. Segurança do servidor: firewall liberando só 80, 443 e SSH (`ufw`); acesso SSH por chave; atualizações
   automáticas (`unattended-upgrades`). O banco **não** é exposto: só o container do site conversa com ele.

## 5. Backup (importante)

```bash
./bin/backup.sh              # guarda banco + arquivos em ./backups (últimas 14 cópias)
./bin/restaurar.sh backups/banco_AAAA-MM-DD_HHMM.sql.gz
```

Agende todo dia (`crontab -e`): `0 3 * * * cd /opt/gestao && ./bin/backup.sh`.
**Copie a pasta `backups` para outra máquina** — backup só na mesma máquina não protege se ela quebrar.
